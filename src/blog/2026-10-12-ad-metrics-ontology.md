上一篇[《广告业务规则怎么抽象成本体》](/blog/2026-10-12-ad-rules-ontology/)讲的是"规则",这篇讲指标。很多团队的指标体系就是一张指标清单:名称、口径、负责人。清单的问题在于它丢掉了结构——而排障、对账、语义层消歧,吃的全是结构。

## 总纲:指标体系四要素

```
指标体系 = 度量(Measure) + 维度(Dimension) + 口径(Caliber) + 关系(Relation)
           有哪些数      按什么切        怎么算准        谁派生谁/怎么分解
```

落到本体上,最重要的一句是:**指标是一等实体(MetricDef),不是报表里的一个字段。**

## 六层漏斗指标清单

按流量旅程排序:从"有多少水"到"体系的体温计"。

### L1 流量/供给层

| 指标 | 口径要点 | 坑 |
|---|---|---|
| 广告请求数 | SDK 发起的请求 | 含超时请求 |
| 有效请求 | 过滤黑名单/频控后 | fill rate 分母用哪个?**必须显式声明** |
| 返回数 | 广告源有广告返回 | 无返回 ≠ 无填充(还有无竞价) |
| **fill rate 填充率** | 填充/请求 | 无标准分母,同名不同义之首 |
| DAU/MAU、人均请求、人均时长 | 供给质量 | 跨 APP 聚合去重口径 |
| 可竞价流量占比 | 支持 Bidding 的流量比例 | 数十个源里多少支持并行竞价 |

### L2 竞价层

| 指标 | 口径要点 | 坑 |
|---|---|---|
| 竞价数/出价数 | 进入竞价 ≠ 有出价(低于底价不出) | 分母链:请求→竞价→出价→胜出 |
| **win rate 胜出率** | 胜出/出价 | 平台侧看不到全部对手价(信息不对称) |
| 平均出价/**平均成交价(win_price)** | **两套价** | 收入必须用 win_price |
| 底价命中率 | 成交价=底价的比例 | 命中率高 = 定价保守,可调底价 |
| 竞价密度 | 平均每请求出价方数 | 平台健康度核心指标 |
| 超时率 | 竞价预算 200ms 内未返回比例 | 超时 = 无填充(不是错误) |

### L3 展示层

| 指标 | 口径要点 | 坑 |
|---|---|---|
| **曝光数** | **三套账**:计费口径/第三方监测/客户端上报 | 同名不同义之首 |
| 可视化曝光率 | MRC:≥50% 像素、静态≥1s/视频≥2s | 与计费曝光的差值 = 质量损耗 |
| 播放完成率(视频) | 完播/开播 | 激励视频接近 100%(用户有动机)——形态间不可比 |
| 渲染失败率 | 客户端渲染异常 | 归因于哪侧(SDK/素材/网络)要拆 |

### L4 互动层

| 指标 | 口径要点 | 坑 |
|---|---|---|
| 点击数 | 有效点击(过滤误触/机器) | 原始点击 vs 有效点击差值即 IVT 线索 |
| **CTR** | 有效点击/计费曝光 | 不同形态间不可直比(横幅 vs 开屏差一个量级) |
| 误触率 | 短时间(<1s)离开落地页的点击占比 | 插屏重灾区 |
| 转化数/**CVR** | 归因口径(Last Click、窗口) | **窗口一变历史全变**——重述问题 |
| 深度转化(次留/付费/LTV) | 回传链路决定可得性 | S2S 回传延迟与丢失率 |

### L5 收入/价值层

| 指标 | 口径要点 | 坑 |
|---|---|---|
| **收入** | 扣减链:计费收入−IVT−退款−返点 | 平台账 vs 监测账(对账差异率) |
| **eCPM(收益口径)** | 收入/曝光×1000 | 与 L2 的"成交 eCPM"同名异源:一个自上而下(收入反推),一个自下而上(竞价聚合)——**对不上本身就是数据质量问题**,这俩的差值是个对账指标 |
| 实际 CPC/CPA | 收入/点击、收入/转化 | 与报价 CPC/CPA 区分 |
| ARPU/人均收益 | 收入/DAU | 媒体侧核心 |
| 分成后收益(媒体侧) | 收入×分成比例 | 三边分账:广告主付钱→平台抽成→媒体拿份 |
| ROI/ROAS、首日 ROI、回收周期 | 广告主侧 | 归因窗口与回本周期错配是深坑 |

### L6 质量/健康层

| 指标 | 说明 |
|---|---|
| IVT 率 | GIVT 可规则判、SIVT 靠模型 |
| 对账差异率 | 平台账 vs 第三方监测,容忍度 ±5% |
| 归因率 | 有归因的转化/总转化——回传链路健康度 |
| 数据新鲜度 | 分钟级大盘 vs T+1 财务的流批差 |
| 学习期通过率 | oCPX 计划过学习期比例 |

## 三边视角:同一漏斗,三套账本

| 边 | 关注层 | 核心指标组 | 一句话关切 |
|---|---|---|---|
| **媒体侧**(变现效率) | L1/L3/L5 | fill rate、eCPM、收入、分成后收益 | "我的流量卖得贵不贵" |
| **广告主侧**(投放效果) | L4/L5 | 消耗、CTR/CVR、转化成本、ROI | "我的钱花得值不值" |
| **平台侧**(撮合健康度) | L2/L6 | 竞价密度、win rate、take rate、IVT 率 | "我的市场活不活" |

**同一次曝光在三边是三个数字**:媒体看到的是 eCPM,广告主看到的是成本,平台看到的是差价。这就是为什么"边"必须是指标的一个维度——没有边,三套账会混成一笔糊涂账。

## 关系体系:派生网络与恒等式

指标体系的价值不在罗列,在**恒等式和分解树**。

### 派生层级

```
原子指标(事件计数:请求数、曝光数、点击数、转化数、金额)
   → 派生指标(比率:fill rate、CTR、CVR、win rate)
      → 复合指标(跨层组合:eCPM、ROI、LTV、ARPU)
```

### 三条核心恒等式

1. **收入 = 曝光 ÷ 1000 × eCPM**——收入异动拆解的主轴;
2. **eCPM = CTR × CVR × CPA × 1000**——漏斗分解:eCPM 降了,是 CTR(素材/人群)还是 CVR(落地页/产品)还是 CPA(竞价环境)?**这是变现诊断之王**;
3. **收入 = 点击 × CPC = 转化 × CPA**——计费模式不同,分解路径不同,但收敛到同一收入。

### 分解树(诊断动线)

```
收入下降
 ├─ 曝光降了?(L1/L3:请求量? fill rate? 渲染失败?)
 │    └─ fill rate 降 → 哪个广告源?超时率升了还是竞价密度降了?(L2)
 └─ eCPM 降了?(恒等式 2 分解)
      ├─ CTR 降 → 素材疲劳? 新人群? 形态结构变化(横幅占比升)?
      ├─ CVR 降 → 落地页? 回传丢失? 归因窗口变更?
      └─ 竞价环境 → 底价命中率变化? 新源接入?
```

出问题时能顺着派生网络走到叶子节点——指标体系就是排障的地图。

## 维度体系:切法就是本体的类层级

| 维度族 | 取值 | 备注 |
|---|---|---|
| 时间 | 自然日/小时/分钟;时区 | 请求时间 vs 计费时间 |
| 供给层级 | 媒体集团→APP→广告位→**形态**(开屏/激励视频/插屏/横幅/原生) | 形态是最强切片,各形态量级不可直比 |
| 地理 | 国家/地区 | 出海业务第一维度(eCPM 国别差 10 倍) |
| 渠道/广告源 | 数十个源;瀑布流层序 | 源 × 层序是排障常用组合 |
| 流量交易类型 | PDB/PMP/OA/兜底 | 与优先级公理联动 |
| 行业/广告主 | 一级行业→细分 | 与黑名单/准入约束联动 |
| 设备/OS | iOS/Android、机型档 | ID 体系差异(IDFA vs OAID) |
| 人群 | 定向包/lookalike | 隐私约束下收紧的维度 |

**维度设计的第一原则**:维度取值必须是**受控词表**(本体里的类),不能是自由文本——"开屏"被写成"开屏/开机屏/启动页"三份,聚合就废了。

## 口径陷阱速查

三套账(平台/监测/客户端)｜同名不同义(曝光、eCPM 两义、消耗口径)｜分母歧义(fill rate)｜bid vs win_price｜预测值 vs 实测值(pCVR 混进实测 CVR 是大事故)｜窗口变更即重述。

## 落点:MetricDef 作为一等实体

| 四要素 | 本体落点 | 工程形态 |
|---|---|---|
| 度量 | **MetricDef**:名称/业务定义/计算式/**分子/分母/去重键/过滤条件**/时间口径/数据源绑定/版本 | 指标目录 |
| 维度 | 受控词表=类层级;指标×维度的可用组合是约束(不是所有指标都能按所有维度切——预聚合边界) | 维度表+组合白名单 |
| 口径 | MetricDef 字段+口径变体(`Impression` ⊳ `Billing/Viewable`) | 同名指标多版本,ChatBI 消歧的输入 |
| 关系 | 派生边(原子→派生→复合)+ 恒等式校验规则 | 图上的 derives 边;恒等式两边对不上 = 对账 DQC |

### 三个缝合动作

1. **指标目录向量化**——用户问"上个月游戏收入",能命中正确的 MetricDef(语义层/ChatBI 消歧的知识底座);
2. **指标节点进拓扑图**——MetricDef 是数据拓扑图的一等资产节点,改上游表先算指标影响闭包;
3. **恒等式变 DQC**——收入 = 曝光×eCPM/1000 两边对不上就告警,指标体系自带体检。

这套结构直接回答语义层最常被问的问题:"大模型为什么答不对指标?"答:不是模型不行,是指标的定义(分子分母、去重键、口径版本、可用维度组合)从来没被结构化过。MetricDef 就是把这些从注释和老人的脑子里搬进图里。
